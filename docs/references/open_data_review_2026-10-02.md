- Per-release README.txt: *"By feeding adsb.lol, you agree to the extent possible under law, to waive all copyright and related or neighboring rights to your data, associating your work with the CC0 license."* This covers the feeders' contributions. The database itself is ODbL.

**ODbL obligations** (`LICENSE-ODbL.txt` in the repo, sections 4.2 to 4.6):
- **4.3 (Produced Work, e.g. our predictions and paper).** A notice is required: *"Contains information from DATABASE NAME, which is made available here under the Open Database License (ODbL)."*, with hyperlinks to the database and the licence.
- **4.4 (share-alike).** *"Any Derivative Database that You Publicly Use must be only under the terms of: i. This License …"* and *"Extraction or Re-utilisation of the whole or a Substantial part of the Contents into a new database is a Derivative Database"*. This applies to a published per-flight surface-feature table, for example.
- **4.6.** If we publicly use a Derivative Database or a Produced Work from one, we must offer *"the entire Derivative Database; or … the method of making the alterations … (such as an algorithm)"*. Our GPL code that builds the features satisfies 4.6(b).
- **4.5(c).** Internal use is not public use.
- In practice: attribute it, publish the extraction code (we do anyway), and license any published derived feature table under ODbL, not GPL.

**Release naming and structure** (GitHub API, all releases listed):
- Tags look like `v2025.07.15-planes-readsb-prod-0`, `v2025.07.15-planes-readsb-staging-0` and `v2025.07.15-planes-readsb-mlatonly-0`.
- June 2025 also has `-prod-0tmp` and `-staging-0tmp` tags (21 days).
- The 2025 repo also holds 2024-12-29 to 2024-12-31.
- Each day's tar is split into parts `….tar.aa`, `….tar.ab` and, on large days, `….tar.ac`. Every part except the last is exactly 2,000,000,000 bytes. 2025-12-25 is a single unsplit `.tar`.
- **Files per day: 2 or 3 parts for one release.** Download only one of prod or staging, never both.
- `mlatonly` is 0.1 to 0.36 GB/day but holds only MLAT positions, so it is useless here.
- To extract: `cat X.tar.aa X.tar.ab | tar -xf - -C dir` (README).

**Download URL pattern:** `https://github.com/adsblol/globe_history_{YYYY}/releases/download/v{YYYY.MM.DD}-planes-readsb-{prod|staging}-0/v{YYYY.MM.DD}-planes-readsb-{prod|staging}-0.tar.{aa,ab,ac}`. Range requests are supported (`accept-ranges: bytes`).

**Checksums.** The GitHub release API now returns `digest: "sha256:…"` for each asset, e.g. `repos/adsblol/globe_history_2026/releases/tags/v2026.07.15-planes-readsb-prod-0`. These are usable as reference hashes for the manifest.

**`PREFERRED_RELEASES.txt`** (repo root; 367 lines for 2025, 292 for 2026):
- One line per day, with that day's part URLs comma-separated.
- It is generated by `update-releases.py`, which for each date keeps the release with the **largest total asset size** (`if assets_size > preferred_releases_per_day[date][1]`) across prod, staging and tmp tags.
- `ALL_RELEASES.txt` lists every release.
- The README rule: *"Download both files from the prod or staging release for a day you're interested in. (if prod or staging for that day is significantly smaller, ignore it)"*.

**Internal format** (inspected the first 36 MB of the 2026-01-15 prod tar):
- Entries are `./traces/<last-2-hex>/trace_full_<icao24>.json`, one file per aircraft per day.
- Each file is **gzip-compressed JSON** despite the `.json` name. Readsb trace format: https://github.com/wiedehopf/readsb/blob/dev/README-json.md#trace-jsons
- A file is `{icao, r (registration), t (type), desc, timestamp, trace:[[dt, lat, lon, alt_ft|"ground"|null, gs_kt, track (true heading when on ground), flags, vrate, {details incl. flight/callsign}|null, source, geom_alt, geom_rate, ias, roll], …]}`.
- **Ground positions are included** (`alt == "ground"`). Example: EI-ENW at EGKK, about 1 to 5 s cadence, speed and heading present.
- Flags bit 2 marks "start of a new leg".
- There is also a `heatmap/` directory for replay, not seen in the first 36 MB.
- About 991 aircraft files were in the first 36 MB. Extrapolating, there are about **80,000 to 90,000 per-aircraft files per day** (estimate, not measured on a full day).

**No smaller per-region or per-airport extract exists.**
- The repos only publish whole-world daily tars.
- Files are grouped by the last 2 hex digits of ICAO24, so no byte range maps to an airport.
- A web search found no maintained per-airport parquet derivative.
- The only way to cut volume is stream-processing (`curl … | tar -x` → filter → delete).

- This is GPL-2.0-or-later, so it is compatible with our GPLv3.
- Supporting text from https://developer.x-plane.com/article/airport-data-apt-dat-1050-file-format-specification/ : *"The GNU GPL (general public License) under which this data is released is designed to encourage modifications, enhancements and redistribution…"*.
- Snapshot the README.txt and COPYING into `docs/references/licences/`.

**API** (https://gateway.x-plane.com/api, docs page fetched):
- `GET https://gateway.x-plane.com/apiv1/airport/{ICAO}` returns metadata plus `recommendedSceneryId`.
- `GET https://gateway.x-plane.com/apiv1/scenery/{id}` returns JSON with `masterZipBlob`, a base64 zip containing `{ICAO}.dat` (the apt.dat), `{ICAO}.txt` (the DSF text) and `{ICAO}_Scenery_Pack.zip` (which holds COPYING, README.txt, `Earth nav data/apt.dat` and `.dsf`).
- `GET /apiv1/releases` and `/apiv1/release/{xp_version}` let you pin to the packs that shipped in a given X-Plane release, which is useful for reproducibility.
- Pin the scenery ID in the config, not "recommended", because recommended changes.

**Verdict.** A trivial, safe source of runway thresholds and headings. It can stand in for or cross-check apt.dat `100` rows. Effort about 1 to 2 h.

## 4. OpenStreetMap aeroway features (Overpass API)

**Licence.** https://www.openstreetmap.org/copyright : *"OpenStreetMap is open data, licensed under the Open Data Commons Open Database License (ODbL) by the OpenStreetMap Foundation (OSMF)."* and *"You are free to copy, distribute, transmit and adapt our data, as long as you credit OpenStreetMap and its contributors. If you alter or build upon our data, you may distribute the result only under the same license."* Required credit: "© OpenStreetMap contributors". The same ODbL obligations as section 1 apply.

**Query used** (tags plus centroids; 2.3 MB for all 10 airports):
```
[out:json][timeout:170];
area["aeroway"="aerodrome"]["icao"="EDDF"]->.a;
nwr(area.a)["aeroway"~"^(parking_position|gate|holding_position|runwayhold|deicing_pad|apron|taxiway|taxilane|runway|stand|stopbar)$"];
out tags center;
```

For the taxi network, use `out geom;` instead of `out tags center;`, which returns full way geometry and is several times larger. For reproducibility, add a snapshot date, e.g. `[out:json][timeout:170][date:"2026-10-01T00:00:00Z"];`; check the Overpass QL docs before relying on this.

**Operational notes:**
- POST to `https://overpass-api.de/api/interpreter` with `--data-urlencode "data=…"` and a **User-Agent**. The default curl UA got HTTP 406.
- There were frequent 504s, so retry with backoff.
- The mirror `overpass.private.coffee` served **stale data**: `osm_base` was 2026-06-01 for EDDM and 2026-05-06 for EGLL, versus 2026-10-02 on the main server. Record `osm3s.timestamp_osm_base` in the manifest.

**Completeness.**
- "pp" means `aeroway=parking_position`.
- "Rows match" is the share of challenge DEP rows whose stand matches a pp `ref` (or `name`).
- "gate" is `aeroway=gate`. These are **terminal gate numbers (B24/B26, D23, …), not stand codes**, so they match poorly. Use `parking_position`, not `gate`.

**Signal check** (read-only query against `raw_training`, DEP rows with target from 0 to 10,800 s):
- EUROCONTROL monthly mean actual taxi-out is `(TOTAL_REF_TIME_MIN + TOTAL_ADD_TIME_MIN) / TOTAL_REF_NB_FL`.
- Across 2025 airport-months, its correlation with our target mean is **0.82**, the regression slope is 0.99, and the mean offset is +0.61 min (target minus EC).
- Examples: EGLL Jan 2025 22.14 (EC) vs 22.18 (target); EHAM Jul 2025 13.10 vs 13.11.
- Notable exceptions: EDDM Jan 2025 11.76 vs 14.50, and LFPG Jan 2025 15.58 vs 17.89, which are likely label defects or de-icing scope.
- 2026 levels a 2025-trained model cannot know: **EHAM Jan 2026 is 16.37 min vs 13.39 in Jan 2025 (+3.0 min; additional time 7.03 vs 4.30)**, and LIRF Jul 2026 is 20.23 vs 21.40.

**Fair-play note.** These are ranking-period aggregates of a closely related quantity. The organizer said yes, but log the decision in `docs/OPEN_QUESTIONS.md` and in METHODS.

**Feasibility.** About 25 MB, minutes to fetch, effort about 0.5 day.
